# Java Edition 26.4 Snapshot 8

Snapshot 7を継承する開発バージョンです。launcher IDは`26.4-snapshot-8`、data pack formatは127.0です。loot系resourceの参照・実行context検証、command report形式、氷の環境音tag、Freezing耐性、Cold Sulfur Cubeを更新します。[^source-5f444d6360][^source-9c296fb69d]

## metadata

```json
{
  "pack": {
    "description": "26.4-snapshot-8 data pack",
    "min_format": [127, 0],
    "max_format": [127, 0]
  }
}
```

## コマンド

- loot系引数のvalidation errorはfunctionとconsoleの両方でコマンドのcompileを失敗させる。`execute if predicate`は`minecraft:command_predicate`、`item ... modify`は`minecraft:command_modifier`を使う
- `commands.json`では引数型を`argument.type`、制約とcontextを`argument`直下に記録する。旧`parser`／`properties`から移行し、`custom_suggestion`／`permissions`も記録する。[新旧reportの読み分け](../reference/command-tree.md#264-snapshot-8のcommand-report)
- Snapshot 7比でnode path・node type・実行可能位置・redirectは一致する。parser IDは変わり、数値・文字列等は`brigadier:`から`minecraft:`へ、`resource_key`／`resource_or_tag_key`の参照は対応する`resource`／`resource_or_tag`へ移る
- 正規表現用`minecraft:pattern`引数型はserver-side mod／plugin向けで、生成したvanilla command treeには使用nodeがない。vanillaで使える構文として生成しない
- `effect`の失敗メッセージを修正（MC-313053）。Snapshot 7の効果tagと時間引数の上限は継承する

## JSON/NBT/registry

- `loot_table`／`predicate`／`item_modifier`／`slot_source`／`context_float_provider`／`context_int_provider`／`villager_trade`と、advancementのtrigger、enchantment effectの`requirements`では、多くのvalidation issueがelement読込を妨げなくなる。JSON構文やcodecの不正まで許されるとは扱わない
- ID／tagをたどる再帰参照と、実行時のcontextが供給できない必須値はerror。条件のない処理と、条件が成立し得る処理を検証する。条件付きの箇所は`number_dispatcher`のcase、`villager_trade.merchant_predicate`、loot pool／entry／functionの`condition`。[検証の選び方](../validation.md#264-snapshot-8のcontext検証)
- context key setの`minecraft:command`を`minecraft:command_predicate`／`minecraft:command_modifier`へ分割。新report `loot_context_requirements.json`に32 contextの`allowed`／`required`を記録する
- `minecraft:command_suggestion_type` registryを追加。report上は`elements: false`／`tags: true`。独自の補完実装をdata packのJSONから登録できるとは解釈しない
- `#minecraft:triggers_ambient_ice_block_sounds`と`#minecraft:triggers_ambient_ice_crystal_sounds`を追加。vanillaの値は順に`minecraft:ice`／`minecraft:packed_ice`。Frostbiteの投擲音`minecraft:entity.frostbite.throw`を追加
- `#minecraft:immune_to_freezing`は`#minecraft:undead`、Polar Bear、Snow Golemを含む。Ice Ballの速度に掛ける基礎damage係数は1.395から1.3へ変わる。係数を実際に減るhealthと同一視しない
- Cold Sulfur Cubeの`buoyant: true`を削除（省略時はfalse）。`replace_disk`内の`matching_fluids`に`"state": {"source": "true"}`を追加し、流水を凍らせない
- Ender Dragonの飛行、騎乗entityへのknockback、canyon生成とnoise settingsの`min_y`の不一致、Netherのravine、debug worldの重複entity、tooltipの削除済みcomponent参照の警告等を修正。resource schemaの追加とは区別する

## 互換性

単一対象のmetadataは127.0へ固定します。Snapshot 7以前のreport readerは引数型・制約の新しい配置に合わせます。既存のloot、predicate、provider、modifier等は、それを呼ぶコマンドやresourceごとに参照先とcontextを再検証します。読込時にerrorが出ないことだけで、コマンドがcompileできるとは判断しません。

Snapshot 7の効果tag、時間上限、equipmentのsaddle、削除済みtagを引き継ぎます。resource pack format 103.0、描画、翻訳、network protocolの変更はデータパック仕様と分けます。

## JSONパラメータ差分

- **item**: `tooltip_display.hidden_components`の削除済みcomponent参照の警告を修正。新item IDの追加なし
- **dimension/worldgen**: canyon／Nether ravineの生成を修正。Snapshot 6のdensity function／corner constraintを継承
- **enchantment**: effectの`requirements`のvalidationを変更。必要なcontext値をeffectの使用箇所で照合する
- **variant**: Cold archetypeは浮かず、水源だけをFrosted Iceへ変換。villager tradeの`merchant_predicate`もcontext検証の対象
- **predicate**: 再帰・context不足を検証し、コマンドは`minecraft:command_predicate`を使う。`immune_to_freezing`の内容を変更
- **advancement**: trigger fieldのvalidationを変更。vanillaのadvancement JSONに差分なし
- **loot_table**: pool／entry／functionの`condition`と実行contextを照合。vanillaのloot JSONに差分なし
- **recipe**: Snapshot 7を継承。vanilla recipe JSONに差分なし
- **item_modifier**: コマンドでは`minecraft:command_modifier`を使用し、`tool`が必要な`minecraft:apply_bonus`等を拒否する

## AI 生成規則

- launcher IDを`26.4-snapshot-8`、formatを127.0へ固定し、project設定では`experimental_features: true`を要求する。未収録の正式`26.4`へ丸めない
- `commands.json`の`argument.type`／`argument.context`と`loot_context_requirements.json`を参照する。補完情報を利用可能な構文や権限の保証として扱わない
- IDとtagを展開して再帰参照を避ける。実際に通る処理が要求するcontext値を呼び出し元の`allowed`と照合する。任意値の実行時の有無も確認する
- `minecraft:command`を新しいcontext IDとして出力しない。コマンド用modifierへ`tool`依存処理、entity computeへ`enchantment_level`依存providerをそのまま流用しない。条件付き処理は各contextで条件が成立し得るかを確認する
- Snapshot 7の効果tag・時間上限・saddleと、`swimming`／`flying` entity type tag・`twisting_vines` block sound setの削除を継承する。`swimmable` fluid tagは保持する
- `upscale`の軸別設定、Y軸だけの`gradient` anchor、`domain_warp`のoffset、`corner_constraint`の件数と値域を維持する
- 旧fluid ID／`falling`、旧耐性tag、`minecraft:intentionally_empty`を出力しない。Coldのvanilla挙動を再現するなら浮力を既定falseとし、水源だけを`source`で選ぶ

## 検証

Mojang公式記事・manifestを照合し、server JARのSHA-1 `5c4d729eca710d0a83b2d54a2cc94216b568385c`を検証しました。JAR内`version.json`でformat 127.0、Java 25、`stable: false`を確認しています。

report／vanilla data生成は成功。Snapshot 7比で3ファイル追加、削除なし、10ファイル変更（data generatorの`.cache`を除外し、ハーネス来歴metadataを含む）です。command treeの構造、新旧引数形式、contextの値、registry差分と新規tagを照合しました。JARで条件付きvalidationの分岐、Coldの浮力の既定値、Ice Ballのdamage係数を確認しました。

server reload／ゲーム内動作検証は未実施です。Minecraft WikiはHTTP 403で取得できず、cross-checkは未実施です。
