# Java Edition 26.4 Pre-Release 1

[Snapshot 10](26.4-snapshot-10.md)を継承する開発バージョンです。launcher IDは`26.4-pre-1`、data pack formatは128.1です。item tooltipの折り返し制御、地形補間の軸順、座標parser、lootとDispenserの動作に変更があります。[^mojang-pre-1][^manifest-v2]

## metadata

```json
{
  "pack": {
    "description": "26.4-pre-1 data pack",
    "min_format": [128, 1],
    "max_format": [128, 1]
  }
}
```

## コマンド

- serverの起動中はコンソールから送ったコマンドが拒否される。起動完了を待って送信し、過去に送ったコマンドが後から実行されると仮定しない
- 中央補正が有効な3D座標引数では、絶対整数のX／Zを0.5ずらし、Yは指定値を使う。例として`10 64 -4`は`10.5 64 -3.5`になる（MC-313274）
- `rotate`でmobの上下の回転、`debug function`で実行時の型変換エラーを修正。生成`commands.json`はSnapshot 10と一致し、2D local座標、文字列引数型、slot sourceの規則を継承する[^mojang-pre-1][^server-pre-1]

## JSON/NBT/registry

- `minecraft:tooltip_display`に任意のboolean `split_lines`を追加。既定は`true`で、`false`で自動の行分割と単語折り返しを無効にする。例は[アイテムのJSON仕様](../json-parameters/items.md#264-pre-release-1のtooltip_display)
- `minecraft:upscale`の補間順をZ→X→YからX→Z→Yへ変更。JSONの`input`、`x`／`y`／`z`と各軸の`mode`・`cell_size`は継承する。既存の軸設定を入れ替えず、地形生成結果を再確認する
- Dispenserの`carved_pumpkin`はgolem生成→`equip_sulfur_cube`→`equip`、`glowstone`はRespawn Anchor充填→`equip_sulfur_cube`→`drop_item`。射出できないitemで`shoot_projectile`が後続behaviorへ進むよう修正。重ね置きできるblockでの`place_block`、`transform_block`の向きと耐久消費、Sulfur CubeのTNT・装備・ブラシ関連も修正
- itemでentityと相互作用した際にuse cooldownが適用される。Cold Sulfur Cubeのfrosted ice生成は`mob_griefing`に従う。移動時に位置依存のarchetype属性効果が更新される
- context依存integer provider `div`では`-2147483648 / -1`がoverflowで評価に失敗する。loot entryの`group`は子が1つの場合も子の展開失敗だけで外側の`sequence`を止めない。group自身のconditionは引き続き適用する
- `loot_context_requirements.json`の出力順を安定化。Snapshot 10から32 contextのallowed／required集合に変更なし。生成registryのIDも一致する
- 同梱の構造NBT 1,511件を展開して比較。各ファイルの`DataVersion`が5130から5131へ更新され、それ以外の展開後データは一致する[^mojang-pre-1][^server-pre-1]

## 互換性

対象を`26.4-pre-1`に固定し、単数形folderと128.1のmetadataを使います。開発バージョンのためproject設定は`experimental_features: true`を要求します。`split_lines`はこのPre-Releaseから生成できます。補間順はJSONに現れないため、既存のworldgen packでは同じseed・設定で生成結果を比較します。

resource pack formatは104.0、world versionは5131、protocol versionは1073742173です。[^server-pre-1]

## JSONパラメータ差分

- **item**: `minecraft:tooltip_display.split_lines`を追加。entityへのitem使用でcooldownを適用。2種のvanilla dispense behavior listを更新
- **dimension/worldgen**: `upscale`の補間順をX→Z→Yへ変更。`ore_vein`が共有density functionを評価する際の性能を修正。構造NBTの`DataVersion`は5131
- **enchantment**: Snapshot 10のeffect contextを継承。共通のinteger provider評価に`div`のoverflow修正を適用
- **variant**: Cold Sulfur Cubeのgamerule遵守と位置依存属性効果の再評価を修正
- **predicate**: context集合とvanilla JSONを継承。`div`でoverflowする入力は評価失敗として扱う
- **advancement**: Snapshot 10の形式とvanilla JSONを継承
- **loot_table**: 子が1つの`group`で展開失敗した場合の`sequence`継続を修正。vanilla JSONの差分なし
- **recipe**: Snapshot 10の形式とvanilla JSONを継承
- **item_modifier**: component操作で`tooltip_display.split_lines`を設定可能。loot context集合はSnapshot 10と一致

## AI 生成規則

- launcher IDを`26.4-pre-1`、formatを128.1に固定し、project設定へ`experimental_features: true`を要求する
- `tooltip_display.split_lines`はbooleanで出力し、通常は省略する。行分割・折り返しの無効化を要件で指定された場合は`false`にする
- `upscale`の`input`、軸別`mode`／`cell_size`は維持し、X→Z→Yの補間順で再検証する。Y軸だけのgradient anchor、domain_warp、corner constraintの制約を保つ
- 中央補正がある3D絶対整数座標ではX／Zの補正、Yの指定値を使う。2D local座標では2値とyawを使用し、`^`と`~`を混在させない
- command reportの`argument.type`と文字列引数型を読み、loot等は`argument.context`と`loot_context_requirements.json`から必須値と再帰制約を確認する。子が1つの`group`を、失敗で停止する`sequence`と同じ条件に使わない
- dispense behaviorはroot list、各entryの`type`、必要なfallbackを明示する。`shoot_projectile`の4必須fieldと音object、通常float providerの制約を維持し、射出可能なitemと失敗時の後続処理を検証する
- Boat／Minecartの`entity_data.id`はitemの種類に合わせる。particleのradius／pop_chance、slot sourceの空slot・0件、Coldの浮力・水源判定を引き継ぐ
- Snapshot 8で使えなくなった旧fluid ID／状態、耐性tag、音IDを生成しない
- `div`の32-bit overflowで得られる巻き戻し値を前提にしない。serverコンソールのコマンド送信は起動完了後に行う

## 検証

Mojang公式記事とmanifestを照合し、server JARのSHA-1 `7ade6b7bb19a6ffbc3185c9227ab1871bf17e00e`と`version.json`のformat 128.1、Java 25、`stable: false`を確認しました。Minecraft Wikiともformat、DataVersion、主要な変更点を照合しました。[^mojang-pre-1][^manifest-v2][^server-pre-1][^wiki-pre-1]

Snapshot 10との生成物比較では10,465ファイル中6件に差分がありました（生成cacheと来歴metadataを除外）。内訳は組み込みの実験pack 3件の`min_format`、2件のdispense behavior、loot contextの出力順です。ファイルの追加・削除はありません。[^server-pre-1]

別々に2回生成した`loot_context_requirements.json`がバイト単位で一致しました。対象JARのtooltip codecを実行し、`split_lines`の省略と`true`で有効、`false`で無効になることを確認しました。中央補正を有効にした座標parserで、`10 64 -4`が`10.5 64 -3.5`になることも確認しました。128.1を指定した最小packは生成reportを使った静的検査を通過しました。[^server-pre-1]

server reloadとゲーム内動作検証は未実施です。
