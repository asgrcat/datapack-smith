# Java Edition 26.4 Snapshot 10

[Snapshot 9](26.4-snapshot-9.md)を継承する開発バージョンです。launcher IDは`26.4-snapshot-10`、data pack formatは128.0です。Mojangはマルチプレイ画面のスクロールで発生するクラッシュ（MC-313265）の修正を公表しています。[^mojang-snapshot-10][^manifest-v2]

## metadata

```json
{
  "pack": {
    "description": "26.4-snapshot-10 data pack",
    "min_format": [128, 0],
    "max_format": [128, 0]
  }
}
```

## コマンド

Snapshot 9の2D local座標、文字列引数型、`schedule`の時間制約、slot sourceの評価規則を継承します。2D local座標は`forceload`のchunk指定用座標、`spreadplayers <center>`、`worldborder center <pos>`で2値とY軸周りの回転を使用します。生成した`commands.json`はSnapshot 9と一致します。[^server-snapshot-10]

## JSON/NBT/registry

- `dispense_behavior` registryと同名のitem component、Boat／Minecartの既定`entity_data`、`current_down`の必須`radius`、`bubble_column_up`の任意`pop_chance`を継承する。[Dispenser behaviorの仕様](../reference/dispense-behaviors.md)
- 公式JARに同梱される構造NBT 1,511件の`DataVersion`が5129から5130へ更新された。展開後のバイト列はこの値の更新箇所以外で一致する。[^server-snapshot-10]

## 互換性

単一対象のmetadataは128.0、配置は単数形folderです。実験利用を明示し、対象ゲームのlauncher IDを固定します。resource pack formatは104.0を継承します。world versionは5130、protocol versionは1073742172です。[^server-snapshot-10]

## JSONパラメータ差分

- **item**: Snapshot 9の`dispense_behavior`とBoat／Minecartの`entity_data`を継承
- **dimension/worldgen**: Snapshot 9のJSONを継承。構造NBTは`DataVersion`を5130へ更新
- **enchantment**: Snapshot 9のeffect context検証を継承
- **variant**: Snapshot 9のregistryと`entity_data`の種類制約を継承
- **predicate**: Snapshot 9のdamage type tagとslot sourceの評価規則を継承
- **advancement**: Snapshot 9の形式とvanilla JSONを継承
- **loot_table**: Snapshot 9の形式、context制約とvanilla JSONを継承
- **recipe**: Snapshot 9の形式とvanilla JSONを継承
- **item_modifier**: Snapshot 9の形式と空slotの評価規則を継承

## AI 生成規則

- launcher IDを`26.4-snapshot-10`、formatを128.0へ固定し、project設定へ`experimental_features: true`を要求する。未収録の正式`26.4`へ丸めない
- dispense behaviorはroot listと各entryの`type`を生成する。registry entryのID、behavior type ID、item componentを区別し、後続へのfallbackが必要なら明示する
- `shoot_projectile`の4必須fieldと値域を守る。音objectを指定する場合は全必須fieldを揃え、通常float providerを使う
- Boat／Minecartの`entity_data.id`を対象種類に合わせる。任意itemへbehaviorを付けるだけで射出・配置が成功するとは断定しない
- 2D local座標は2値とyawだけで解釈する。`^`と`~`を混在させない。particleのradiusとpop_chanceの型・既定値・値域を守る
- command reportの`argument.type`と文字列引数型を読む。loot等は`argument.context`と`loot_context_requirements.json`から必須値と再帰を確認する
- slot sourceのfilter・limit・groupと空slot、source 0件を再検証する。通常の静的検査をゲーム内compile・動作検証と同一視しない
- Coldの浮力falseと水源判定、旧fluid／耐性tag／音IDの削除、upscaleの軸別設定、Y軸gradient anchor、domain_warp、corner constraintの制約を維持する

## 検証

公式記事とmanifestを照合し、server JARのSHA-1 `d713516162441e0961e1ccfb85d8feeb01b50fd6`を確認しました。`version.json`でdata pack format 128.0、Java 25、`stable: false`を確認しています。[^manifest-v2][^server-snapshot-10]

生成cacheとハーネスの来歴metadataを除いた10,465ファイルをSnapshot 9と比較しました。コマンド、registry、vanilla dataは一致し、`loot_context_requirements.json`もallowed／requiredの並び順を除いて一致しました。同梱の構造NBTは生成物に含まれないため、両方のJARから直接比較しました。[^server-snapshot-10]

server reload／ゲーム内動作検証は未実施です。Minecraft WikiはHTTP 403で取得できず、cross-checkは未実施です。[^wiki-snapshot-10]
