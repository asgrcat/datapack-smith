# Java Edition 26.4 Snapshot 9

Snapshot 8を継承する開発バージョンです。launcher IDは`26.4-snapshot-9`、data pack formatは128.0です。Dispenserのデータ駆動behaviorとitem component、2D local座標、particle field、command reportとslot sourceの修正を収録します。[^mojang-snapshot-9][^manifest-v2]

## metadata

```json
{
  "pack": {
    "description": "26.4-snapshot-9 data pack",
    "min_format": [128, 0],
    "max_format": [128, 0]
  }
}
```

## コマンド

- `forceload`のchunk指定用座標、`spreadplayers <center>`、`worldborder center <pos>`で2D local座標`^<left> ^<forwards>`を受け付ける。回転はY軸周りだけを使い、3Dの`^left ^0 ^forwards`をXZへ投影する意味ではない
- `commands.json`の文字列引数は`minecraft:string`から`minecraft:word`／`minecraft:quoted_string`／`minecraft:greedy_string`へ分離（MC-313181）。たとえばtag名はword、datapack名はquoted string、helpのcommandはgreedy string
- `schedule`で負の時間を指定できる不具合を修正。reportも`schedule function ... time`等の`min: 0`を記録する
- `execute positioned over`の後続引数、`execute if|unless blocks|data`の接続、`rotate`、`say`／`msg`の署名付きmessage、未知IDやtext componentのerror等を修正。reportのnode pathはSnapshot 8と一致するが、同じ動作とは判断しない
- `item`のfiltered／limit_slotsの評価順、group内の入れ子limit、modifyの暗黙の空slot除外、sourceが0 slotの場合のoverrideを修正。slot数・順序・空slotの結果を移行時に再検証する[^mojang-snapshot-9][^server-snapshot-9]

## JSON/NBT/registry

- 新registry folder `dispense_behavior`を追加。各fileのrootは`type`を持つbehavior objectのlistで、通常は順番に試して成功時に停止する。24 typeと27 vanilla entryを生成dataで確認。[型・停止条件・最小例](../reference/dispense-behaviors.md)
- item component `minecraft:dispense_behavior`はregistry entryのIDまたはinline list。componentの設定だけで任意itemをblock item／projectile itemに変えるものではない
- Boat／Minecart itemに`minecraft:entity_data`を既定で追加。通常使用・Dispenser使用の両方でentity typeが対象種類に合わなければ失敗する
- `shoot_projectile`の`offset`／`scale`／`uncertainty`／`power`は必須。`sound`は任意で、指定時は内側の`sound`／`volume`／`pitch`が必須。volume／pitchは通常のfloat providerで、context依存providerとは別codec
- block transformer `minecraft:honeycomb`を追加（現在はDispenserから使用）。既存`minecraft:axe`の一部ruleは`consume_on_use: false`を明示するよう変更。field自体はSnapshot 8にも存在し、省略時trueを継承
- particle `minecraft:current_down`へ必須`radius`（0以上のfloat）、`minecraft:bubble_column_up`へ任意`pop_chance`（0.0〜1.0、既定0.0）を追加。記事のfloat表記に対しradiusの非負制約はJARで確認
- dialogの入力fieldがemail addressらしい場合、赤いtextと警告tooltipを表示。入力を自動拒否・検証する新schemaとして扱わない
- damage type tag `minecraft:cannot_hurt_perching_ender_dragon`を追加し、Arrow／Thrown／Trident／Wind Chargeのdamage typeを列挙。`bypasses_cooldown`へ`minecraft:generic_kill`を追加。damage type IDとentity type IDを区別する
- Pig／Striderのstick使用時のrandom boostは7〜35秒となり、boost状態のNBT保存を修正。Fire／Soul Fireの破壊音に消火音を使用する`minecraft:fire` block sound setを追加。worldgen noise settingsの差分はdebug labelの表示変更
- `loot_context_requirements.json`は順序を除く32 contextのallowed／required集合がSnapshot 8と一致。item component reportは1686ファイル変更され、通常itemにもdispense behaviorの参照を追加[^mojang-snapshot-9][^server-snapshot-9]

## 互換性

単一対象のmetadataは128.0へ固定します。公式記事の「Data Pack Versions 122.0 through 128.0」は収録済みSnapshot 1〜8の仕様へ新registryやcomponentを遡及適用する根拠にしません。対象JARで追加を確認したSnapshot 9を境界にします。

Snapshot 8のcontext・再帰検証と新command report、Snapshot 7の効果tag・時間上限・equipmentのsaddleを継承します。既存particleの書式、slot sourceの結果、Dispenserで使うitemのcomponentを移行時に確認します。

resource pack format 104.0、Vulkan／Improved Fog、keyboard navigation、login protocolと`key-rotation-period-seconds`（既定60）はdata packのJSON schemaと分けます。翻訳key `menu.custom_options*`／`menu.custom_screen_info*`のresource packによる上書き制限も別の変更です。[^mojang-snapshot-9]

## JSONパラメータ差分

- **item**: `minecraft:dispense_behavior`を追加。Boat／Minecartへ既定`entity_data`。vanillaの新item IDは追加なし
- **dimension/worldgen**: Snapshot 8のworldgen codecを継承。noise settingsのdebug labelを更新
- **enchantment**: Snapshot 8のeffect context検証を継承。今回固有のschema変更は公式記事に記載なし
- **variant**: Snapshot 8を継承。entity_dataの種類制約とboost NBTの修正を、variant registryの追加と混同しない
- **predicate**: 新damage type tagとslot sourceの評価修正を反映。contextの値集合はSnapshot 8と一致
- **advancement**: Snapshot 8を継承。vanillaのadvancement JSONに差分なし
- **loot_table**: Snapshot 8を継承。vanillaのloot JSONに差分なし
- **recipe**: Snapshot 8を継承。vanilla recipe JSONに差分なし
- **item_modifier**: item componentでdispense behaviorを設定可能。modify／overrideとslot sourceの選択結果の修正を反映

## AI 生成規則

- launcher IDを`26.4-snapshot-9`、formatを128.0へ固定し、project設定へ`experimental_features: true`を要求する。未収録の正式`26.4`へ丸めない
- dispense behaviorはroot listと各entryの`type`を生成する。registry entryのID、behavior type ID、item componentを区別し、後続へのfallbackが必要なら明示する
- `shoot_projectile`の4必須fieldと値域を守る。音objectを指定する場合は全必須fieldを揃え、通常float providerを使う
- Boat／Minecartの`entity_data.id`を対象種類に合わせる。任意itemへbehaviorを付けるだけで射出・配置が成功するとは断定しない
- 2D local座標は2値とyawだけで解釈する。`^`と`~`を混在させない。particleのradiusとpop_chanceの型・既定値・値域を守る
- command reportの`argument.type`と文字列引数型を読む。loot等は`argument.context`と`loot_context_requirements.json`から必須値と再帰を確認する
- slot sourceのfilter・limit・groupと空slot、source 0件を再検証し、Snapshot 8の不具合を前提に生成しない。通常の静的検査をゲーム内compile・動作検証と同一視しない
- Snapshot 8のColdの浮力falseと水源判定、旧fluid／耐性tag／音IDの削除、upscaleの軸別設定、Y軸gradient anchor、domain_warp、corner constraintの制約を維持する

## 検証

Mojang公式記事・manifestとJARを照合し、server JARのSHA-1 `c969aafcecae7859d466147c6847d63d28d545eb`を検証しました。`version.json`でformat 128.0、Java 25、`stable: false`を確認しています。[^manifest-v2][^server-snapshot-9]

report／vanilla data生成は成功。Snapshot 8比で30ファイル追加、削除なし、1703ファイル変更（生成cacheを除外、ハーネス来歴metadataを含む）です。24 behavior type、27 entry、default component、block transformer、damage type tag、新旧command引数と同一context集合を照合しました。

JARのcodecと処理からprojectileの必須field・音object、radiusの非負制約、pop_chanceの値域と既定値、順序と停止を確認。serverを起動しない2D parser実行で`^1 ^2`／`^ ^`を受理し、`^1 ~2`を拒否することをVec2／ColumnPosの両方で確認しています。

behaviorのlist codecもserver起動なしで実行し、place_block→drop_itemの例、全必須fieldを持つprojectile、空listを受理し、必須fieldのないprojectileを拒否することを確認しました。

server reload／ゲーム内動作検証は未実施です。Minecraft WikiはHTTP 403で取得できず、cross-checkは未実施です。[^wiki-snapshot-9]
