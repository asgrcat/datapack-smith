# Java Edition 26.4 Snapshot 1

正式26.3を継承する26.4の最初の開発バージョンです。launcher IDは`26.4-snapshot-1`、data pack formatは122.0です。正式仕様の基準は[26.3](../versions/26.3.md)とし、このページの差分を明示指定時だけ適用します。

## コマンド

- `/fillbiome`がblock単位の精度でbiomeを変更するようになった
- NBTの浮動小数点型から整数型への変換は、切り下げ後に変換先で表現可能な最も近い値へ変換する。負数のlong変換も0方向への切り捨てとして扱わない（MC-276879）
- `/test`の`rotationSteps`を0〜3へ制限（生成コマンド木で確認）。`/test run`の範囲外`rotationSteps`によるエラーを修正（MC-311786）

## JSON/NBT/registry

- multi-noise biome sourceは、同じoffsetで全noise parameterの範囲が重複する異なるbiomeのentryを許可しない
- `straight_trunk_placer`に省略可能なinteger provider `trunk_width`を追加。原点を中心とする幹幅で、既定値は1（公式記事では1.0表記）
- biomeに含めるplaced featureのXZ配置範囲を検証する。配置位置は3×3 chunk内に収める。feature自体の大きさはこの検証に含まれない
- `cuboid` placement modifierの`xz_size`／`y_size`は実際の大きさを表す。従来の「指定値+1」ではなく、`xz_size: 2`は2×2になる
- `fixed_placement.positions`は1要素以上が必須
- noise settingsの`default_block`を削除。既定blockはairとなり、それ以外のblockはMaterial Ruleで定義する
- material condition `minecraft:steep`はEroded Badlandsのsurface extensionによる高さ変更を順序依存で参照しなくなった
- biome tag `#minecraft:generated_in_below_zero_retrogen`と`#minecraft:is_cave`を追加。前者はCaves and Cliffs以前のworldの地下再生成対象、後者は洞窟biomeの集合
- 古いworldの地下再生成にsulfur cavesを含める。キノコの設置は明るさに依存しなくなったが、拡散条件とは区別する
- item frameの`Facing`変更、方向同期、teleport表示位置の不具合を修正（MC-296053、MC-299060、MC-311788）

## 互換性

26.3向け121.0のmetadataだけを122.0へ変更して移行完了とはしません。worldgenの削除field、配置サイズ、配置範囲、biome sourceの重複を確認します。`/fillbiome`の変更範囲とNBT数値変換に依存する処理も再検証します。

Vulkanの既定化、resource pack format 98.0、network packet変更はデータパックのschemaとは別です。server運用では`allowed-connection-ids`、`status-contact-details`、`enable-legacy-status`が追加されています。接続IDは暗号化されない接続情報であり、認証手段として扱いません。

- **enchantment**: 26.3を継承。固有の変更は公式記事に記載なし
- **variant**: 26.3を継承。固有の変更は公式記事に記載なし

## AI 生成規則

- launcher IDを`26.4-snapshot-1`、data pack formatを122.0へ固定し、未収録の正式`26.4`へ丸めない
- project設定は`experimental_features: true`を要求する
- 正式26.3のcontext依存integer／float provider、参照形式、配置規則を継承し、対象JARのconsumerに合う型を使う
- noise settingsへ`default_block`を出力せず、blockをMaterial Ruleで定義する
- `cuboid`は実寸を指定し、`fixed_placement.positions`を空にしない。placed featureのXZ範囲とmulti-noise biome entryの重複を検査する
- `/fillbiome`の範囲と負の小数から整数への変換を対象JARで確認する
- report／vanilla data、reload、利用するworldgenとentity操作の挙動を対象JARで再検証する

## 検証

公式記事とmanifestを照合。manifest指定server JAR（SHA-1 `1c5ef8ced87763278a406812e7f0932384c3bb44`）を取得・検証し、`version.json`でformat 122.0、Java 25、`stable: false`を確認しました。公式記事のJARリンクとmanifestのSHA-1は異なるため、launcher IDに対応するmanifestのJARを採用しています。

report／vanilla data生成は成功。26.3との差分はbiome tag 2ファイル追加、削除なし、18ファイル変更（ハーネス来歴metadataを含む）です。`default_block`削除、material ruleのstone fallback追加、cuboidサイズ補正を確認しました。registry reportでは`minecraft:chunk_status`へ`minecraft:noise_biomes`が追加されています。これはchunk生成段階のregistryで、独自element用フォルダの追加を意味しません。コマンド木の差分は`/test`の`rotationSteps`を0〜3に制限する3箇所です。server reload／ゲーム内動作検証、および取得できなかったMinecraft Wikiの照合は未実施です。
