# Java Edition 26.3

Wilderness Boundの正式リリースです。data pack formatは121.0、Javaは25です。このプロファイルは26.2からの確定差分をまとめます。snapshot／pre-release／RCは履歴として保存し、正式リリースの継承・生成規則には混ぜません。

## metadata

```json
{
  "pack": {
    "description": "26.3 data pack",
    "min_format": [121, 0],
    "max_format": [121, 0]
  }
}
```

## コマンド

- `/compute <target> integer <int_provider>`と`/compute <target> float <float_provider> [<scale>]`を追加。targetは`default`、`block <pos>`、`entity <selector>`。評価失敗はコマンド失敗、float resultはscale適用後に負の無限大方向へ丸める
- `/data modify ... append|insert|merge|prepend|set compute <target> integer|float <provider>`を追加。integer／float NBTへ直接保存し、scale引数はない
- `/posteffect add|remove|clear|list`を追加。表示にはclient側resource packのpost effectが必要
- `/item`のslotをslot source化。`replace`は順番に置換して余りの対象slotを維持、`fill`はsourceを繰り返し、`override`は余りの対象slotを空にする。`from entity`は複数entityを許可
- `execute if|unless items`はslot sourceを受け、`execute if|unless slots`は選択slot数を判定
- `/publish`のgamemode引数を削除。`/defaultgamemode`と`/gamemode`を使い分ける
- `/place feature`はinline featureを許可。`/spreadplayers`の安全判定は`#minecraft:entities_can_teleport_to`を使用
- `/swing`は`none`／`whack`／`stab`とdurationを指定可能。playerのattack strengthをresetしない
- `/give`、`/unpublish`、`/tick`の失敗通知を厳格化。`team join|leave`のresultは実際に変化したentity数。`tellraw`のNBT text解決は64K回まで

型・fieldの詳細は[number provider](../reference/number-providers.md)、[slot source](../reference/slot-sources.md)、[26.3移行リファレンス](../reference/26.3-migration.md)を参照します。

## JSON/NBT/registry

### 参照と数値計算

- advancement、item modifier、loot table、predicate、recipe、slot source等の対応fieldはinline／ID参照、集合fieldはlist／tagと混在listを許可。専用の旧reference wrapperを削除
- loot functionとloot conditionのdiscriminatorを`type`へ統一。旧condition listを単一predicateとして暗黙解釈しない
- context依存number providerを`context_int_provider`と`context_float_provider`へ分離。type registryも分離し、整数23 type／float28 typeを使用
- 集約演算は`add`／`mul`／`min`／`max`／`avg`と`inputs`を使用。整数のoverflow・0除算・不正変換は失敗。float `mod`は通常の剰余、integer／float `pow`の`0^0`は失敗
- `value_check`を`int_value_check`／`float_value_check`へ分離。loot poolの`rolls`はinteger、`bonus_rolls`はfloat provider
- `context_key_set`は組み込みentryとtagを参照できるが、独自element fileは追加できない

### item・block entity・recipe

- `cooking_fuel`、`brewing_fuel`、`compostable`の数値は用途に応じたinteger／float providerを使用
- `brewing` recipeをデータ駆動化。cooking recipeの`cookingtime`を必須化し、smoking／blastingの旧値は2倍へ移行
- `block_transformer` componentは独立registryのID参照。block state providerは`worldgen/block_state_provider`へ独立定義できる
- `provides_pottery_pattern`を追加。`pot_decorations`とdecorated potの`sherds`はback／left／right／frontのitem stack map
- `sign_text_front`／`sign_text_back`／`waxed`を追加。新規signのclick event等は既定無効で、明示的な`allow_op_features`が必要
- `attack_animation`／`interact_animation`を使用し、`swing_animation`を削除。map関連componentを再編し、`map_color`を削除
- entityに`invulnerable_time`を追加。furnace／brewing standの時間・fuel NBTをinteger化し、speed等のfieldを追加

### worldgen・advancement・trade

- block stateの`Name`／`Properties`を`id`／`properties`へ変更
- `worldgen/configured_feature`→`worldgen/feature`、`worldgen/configured_carver`→`worldgen/carver`へ移動し、`config` wrapperを除去
- material rule／conditionを独立registry化し、noise settings、noise、density function、block state providerを再編
- biomeのspawn設定をenvironment attributesへ移動。bed ruleの`explodes`を`can_sleep`へ変更
- 可視root advancementには`display.background`が必須、子には禁止。triggerのblock／recipe／loot table条件を複数ID対応へ変更
- villager tradeの`given_item_modifiers`→`given_item_modifier`。count／max_uses／xpはinline integer provider、reputation_discountはinline float provider
- Dappled Forest、Poplar、Abandoned Camp、Cushion、Straw Bed、Wool／Concrete Stairs・Slabs、Explorer Mapsを追加。tag・registryの正確なIDは26.3のvanilla dataを使用

## 互換性

26.2の107.1から121.0への移行はmetadata変更だけでは完了しません。[26.3移行リファレンス](../reference/26.3-migration.md)のfield・配置変換を適用し、参照先、predicate、loot、recipe、worldgenを対象JARで検証します。26.2との共通packを作る場合はoverlayまたは別packへ分離します。

RC3からは生成report／vanilla dataの一致を確認していますが、launcher IDとchannelは正式リリース`26.3`／`release`へ切り替えます。正式26.3だけを理由に`experimental_features: true`を要求しません。

## JSONパラメータ差分

- **item**: fuel・compostableのprovider化、pot／sign／animation／map component変更、block transformer ID参照
- **dimension/worldgen**: feature／carver配置、material／block state provider registry、noise／density function、spawn environment attributeを再編
- **enchantment**: predicate／modifier参照と数値providerを整数／floatへ移行
- **variant**: 26.2のvariant registryを基底とし、正式JARで対象entryを解決
- **predicate**: discriminatorをtypeへ統一、旧referenceを直接IDへ変更、value_checkを整数／floatへ分離
- **advancement**: root背景を必須化、triggerのpredicateを明示型へ、block／recipe／loot table条件を複数対応へ変更
- **loot_table**: pool／entryのcondition・modifier参照、rolls／bonus_rollsの型、追加contextを適用
- **recipe**: brewingを追加、cookingtimeを必須化、smoking／blasting時間を移行
- **item_modifier**: function→type、conditions→condition、sequenceと直接参照、数値providerの型、limit_countのrange objectを適用

## AI 生成規則

- launcher IDを正式`26.3`、channelをrelease、formatを121.0へ固定し、開発IDへ置換しない
- 26.2を継承元とし、snapshotの一時的な構文や生成規則を正式仕様として適用しない
- loot function／predicateは`type`、単一conditionは`condition`を使い、旧reference wrapperや暗黙の条件listを残さない
- context依存providerのinteger／floatをconsumerに合わせ、型変換はfrom_int／from_floatで明示する
- 集約演算はinputsを使用し、0除算、overflow、powの0^0、floatの非有限値を検証する
- computeのtarget直後にinteger／floatを置き、data modify computeへscaleを出力しない
- cookingtimeを省略せず、brewingはinput／reagent／outputを使用する
- block_transformerはID、block stateはid／properties、feature／carverは新配置とroot fieldを使う
- 新規signのallow_op_featuresは用途に応じて明示し、暗黙のcommand実行を期待しない
- 26.3のreport／vanilla dataを正本とし、reload、PvP、recipe時間、worldgenの未実施検証を明記する

## 検証
