# 26.3 確定仕様と26.2からの移行

対象は正式Java Edition `26.3`、data pack format 121.0です。26.2の各referenceにある例には、このページの差分を適用します。開発途中の仕様は[snapshot履歴](../snapshots/README.md)へ分離し、正式生成では参照順に積み上げません。

## 正本と配置

正式プロファイルは[26.3](../versions/26.3.md)、数値計算は[number provider](number-providers.md)、slot操作は[slot source](slot-sources.md)、block変換は[block transformation](block-transformation.md)を使います。

| 26.2の配置・値 | 26.3の確定形 |
|---|---|
| `worldgen/configured_feature` | `worldgen/feature`。`config`を外しfieldをrootへ移す |
| `worldgen/configured_carver` | `worldgen/carver`。`config`を外しfieldをrootへ移す |
| inline surface rule／condition | `worldgen/material_rule`／`worldgen/material_condition`として独立定義可能 |
| inline block state provider | `worldgen/block_state_provider`として独立定義しID参照可能 |
| slot値 | `slot_source`として独立定義可能 |
| block変換のitem設定 | `block_transformer`へrule listを置き、componentはID参照 |
| context依存数値 | `context_int_provider`／`context_float_provider`をconsumerごとに選択 |
| block state `Name`／`Properties` | `id`／`properties`。通常のblock stateは既定stateをblock IDで省略可能 |

block state providerの省略形はinline block state objectです。文字列をproviderへ渡すとprovider registryのID参照になるため、単なるblock IDとは区別します。

## Registry参照と条件

対応する単一element fieldはinline objectまたはnamespaced ID、集合fieldは単一element、list、tagを受けます。listでinline値とID参照を混在できます。ただしvillager tradeのinline専用field等の例外は個別に確認します。

| 対象 | 旧形 | 26.3 |
|---|---|---|
| loot conditionの識別子 | `condition` | `type` |
| loot functionの識別子 | `function` | `type` |
| loot function／pool entryの条件 | `conditions` list | `condition`の単一predicate／ID |
| loot pool entryの加工 | `functions` | `modifier`。alternatives／sequence／group entryでも利用可能 |
| predicateの参照 | `minecraft:reference` wrapper | predicate IDを直接指定 |
| modifier／slot sourceの参照 | `minecraft:reference` wrapper | 対応registryのIDを直接指定 |
| 条件listの暗黙AND | plain list | `{"type":"minecraft:all_of","terms":[...]}` |
| loot entry `minecraft:tag` | `name` | `items`（ID／list／tag） |
| loot function `set_loot_table` | `type`（旧table type）、`name` | 旧table type fieldは削除、`loot_table_id`を使用。discriminatorの`type`とは区別 |
| `limit_count.limit` | 単一数値 | `min`／`max`を持つrange object |
| `value_check` | 共通数値判定 | `int_value_check`／`float_value_check`の`value`と`test` |

```json
{
  "type": "minecraft:set_count",
  "count": 2,
  "condition": {
    "type": "minecraft:all_of",
    "terms": ["example:enabled", "example:eligible"]
  }
}
```

この例の2つのpredicate IDは利用packで定義します。旧fieldを機械的に全文置換せず、discriminatorと条件fieldを文脈で区別します。

## Number providerとcontext

| consumer | 値の種類 |
|---|---|
| loot pool `rolls`、set_count、enchant_with_levels、color、amplifier、duration | context integer |
| loot pool `bonus_rolls`、attribute amount、set_damage、custom model data float | context float |
| cooking_fuel.burn_time、brewing_fuel.uses、compostable.layers | context integer |
| cooking_fuel.speed_multiplier、brewing_fuel.speed_multiplier | context float |
| tradeのmax_uses／xp／count | inline context integer |
| tradeのreputation_discount | inline context float |

worldgenのcontext非依存int／float providerと混同しません。整数23 type、float28 typeのfield、丸め、失敗条件は[number-providers.md](number-providers.md)を正本にします。

`command_compute_default`はoriginと任意this_entity、`command_compute_position`はさらにblock state／block entity、`command_compute_entity`はtarget_entityを提供します。`command_slot_source`はcontainerとorigin、任意this_entityを提供します。`container_process`は燃料計算用のcontainer／block entity／block state／originです。

`match_block`は常にblock stateを要求し、NBTまたはcomponent条件があるときだけblock entityも要求します。`context_key_set`の独自elementは追加できません。

`block_state_property`は削除され、block条件には`match_block`を使います。exploration_mapはdestinationが必須、map_colorを削除し、item種別を変更しません。生成するitemはloot entry／trade側でfilled_mapまたはExplorer Mapを指定します。構造物が見つからなければmap_idが付かないため、必要ならfilteredとdiscard_itemで除外します。

`minecraft:potion_contents` predicateは任意`potions`（ID／list／tag）と`effects`（collection predicate）を使います。effectsはcontains／count／sizeで選択し、個別effectのduration／amplifier／ambient／visibleを判定できます。item component値の`potion`（単数）とは区別します。正式JARのPotionsPredicate codecとvanilla brewing recipeで`potions`を確認済みです。

## Advancement

- displayを持ちparentを持たないrootには`display.background`を必ず設定し、子には設定しない
- player／entity／location等のloot条件は型を明示した単一predicateまたはIDにする。暗黙のentity_propertiesや条件listを使わない
- rewards.lootはloot tableのinline／ID／list／tagを受ける
- bee_nest_destroyed、enter_block、slide_down_blockの`block`を`blocks`へ変更。bee_nest_destroyedには`state`も追加
- player_generates_container_lootの`loot_table`を`loot_tables`へ変更
- recipe_crafted／crafter_recipe_craftedの`recipe_id`、recipe_unlockedの`recipe`を`recipes`へ変更
- brewed_potionの`potion`はpotion_contents component predicateを使用
- damage type条件のtags.idもID／list／tagを受ける

## Item・NBT・燃料・recipe

| 項目 | 26.3の仕様 |
|---|---|
| pot_decorations／decorated pot.sherds | back／left／right／frontの任意item stack map |
| provides_pottery_pattern | decorated_pot_patternのID |
| trim_material | asset_name→palette、override_armor_assets削除 |
| instrument | durability_damage（任意・非負整数）、use_durationは0を許可 |
| sign_text_front／sign_text_back | signのfront_text／back_textと同じ形式 |
| waxed | fieldなしのmarker |
| sign.allow_op_features | 既定false。新規signのclick event／text解決を旧動作にする場合は明示 |
| cushion/color | 16 dye colorのいずれか |
| villager_food.nutrition | 正integer |
| mob_visibility | targeting_entity_types（ID／list／tag）とvisibility（0.0〜10.0） |
| attack_animation／interact_animation | typeはnone／whack／stab、durationは非負integer。旧swing_animationは削除 |
| consumable.teleport_randomly | directional_particlesは任意boolean、既定true |
| map_color | 削除。既存mapからload時に除去 |
| entity.invulnerable_time | 一時的な無敵時間（ticks） |

brewing standのBrewTime／Fuel、furnace等のcooking_time_spent／cooking_total_time／lit_time_remaining／lit_total_timeはintegerです。brewing standにはtotal_brew_time／total_fuel／speed_multiplier、furnace等にはspeed_multiplierを追加します。

燃料のremainderは、fuelが残っていればdropし、使い切ればfuel slotへ残します。旧`#brewing_fuel`による登録は廃止しcomponentを使います。

brewing recipeは`type: minecraft:brewing`と次のfieldを使用します。

| field | 型 |
|---|---|
| input／reagent | 必須itemと任意potion_contents predicateを持つobject |
| output | item stack |

例えばbrewingのinput側では`"potion_contents":{"potions":"minecraft:leaping"}`、outputのcomponent値では`"minecraft:potion_contents":{"potion":"minecraft:slowness"}`を使います。公式記事の古い例より正式JARのvanilla JSONを優先します。

cooking recipeの`cookingtime`は必須です。以前省略していた場合は200、smoking／blastingは以前の明示値を2倍にし、fuel provider側で適用される速度と合わせます。

## Worldgenの移行

### Biome・environment attribute

biomeのspawners／spawn_costs／creature_spawn_probabilityを削除し、`minecraft:gameplay/natural_mob_spawns`と`minecraft:gameplay/creature_world_gen_spawn_probability`へ移します。natural_mob_spawnsはspawns_by_categoryとspawn_costsを持ち、spawn entryはentity typeとcount providerです。worldgen時はdimension／biomeの属性だけが適用されます。

bed_ruleのexplodesをcan_sleepへ変更し、straw_bed_ruleも同じ形式を使います。ambient_particlesはtimeline間の確率補間とappend modifierを扱います。sleep可否と、従来の爆発動作を同じbooleanとしてコピーしません。

### Feature・carver

- basalt_columns→stepped_column_cluster、basalt_pillar→single_block_pillar、glowstone_blob→random_neighbor_spreadへ汎用化
- coral_mushroom、kelp、seagrass、sea_pickle、nether_forest_vegetation、twisting_vines、weeping_vines、desert_wellの専用feature typeを削除。vanillaの同名resourceを参考に汎用featureへ再構成
- sculk_patchのextra_rare_growths／catalyst_chanceを削除
- overlay、projected_random_patchy_square、end_podium、Poplar用tree構成、cuboid等のplacementを追加
- cave／canyonは旧configをrootへ移す。replaceable／lava_level／debug_settingsを削除。nether_caveをcaveへ統合
- carver除外は`#minecraft:uncarvable`を使用し、旧overworld_carver_replaceables／nether_carver_replaceablesは使わない
- structure placementのdimension_origin、jigsawのfeature_pool_element、template processor等の変更は正式vanilla定義で確認

### Noise・density function・material

| 対象 | 26.3の確定変更 |
|---|---|
| noise | firstOctave→base_octave、amplitudes→amplitude_modifiers |
| noise | base_amplitude（既定1.0）、octave_count（1〜32）、normalize（booleanまたはlegacy、既定true） |
| amplitude_modifiers | 省略時は全1.0、指定時はoctave_countと同じ要素数 |
| density constant | argument→value |
| density add／mul／min／max | argument1／argument2→left／right |
| density単項演算 | argument→input。shift_a／shift_b／shiftはargument→noise |
| shifted_noise | noiseへ統合しshift_x／shift_y／shift_zを使用 |
| invert | reciprocalへ改名 |
| y_clamped_gradient | gradientへ汎用化 |
| end_islands | end_outer_islandsへ改名 |
| noise settings | surface_rule→material_rule。ore vein処理等もmaterial ruleへ移行 |

noise settingsのaquifers_enabledを任意aquifers objectへ移し、noise_routerのbarrier／fluid_level_floodedness／fluid_level_spread／lavaとsurface_level／exclusionを設定します。ore_veins_enabledとvein_toggle／vein_ridged／vein_gapはore_vein material ruleへ移します。preliminary_surface_levelはchunk_surface_levelへ改名し、暗黙のchunk補間を前提にしません。final_densityにはbeardifierが暗黙加算されません。noise.size_horizontal／size_verticalを削除し、補間設定はinterpolated density functionで指定します。

density functionとnoiseは中間演算もsingle precisionです。旧doubleの丸めを利用した地形は再検証します。sub／div／negate／lerp／丸め／pow／sqrt／log／sign／distance_to_point／slice等の式は、対象registryのtypeとfieldを確認します。

spawn_targetは任意のdensity function IDを軸とするtarget hypercubeのlistです。各軸の値は単一float、2 floatの配列、またはmin／max objectです。旧noise_routerの一部fieldへの固定参照と区別します。

block state provider typeの`_provider` suffixを削除します。rule_basedが結果なしなら後続ruleへ進み、fallbackも結果なしならprovider全体も結果なしです。

## Tag・content・運用

Dappled Forest、Poplar、Abandoned Camp、Cushion、Straw Bed、Wool／Concrete Stairs・Slabs、Explorer Mapの追加を正式仕様として扱います。構造物の検索tagには正式JARの`on_abandoned_camp_windswept_forest`等を使い、開発途中の旧IDを復活させません。

teleportation、portal frame、conduit、potionの消火／水反応、cooking／brewing slot等のtagを対象registryで確認します。全IDの手書き複製ではなく、[coverage](coverage.md)と正式vanilla dataを使用します。

server.propertiesのwhite-listは既定trueです。server logの一部行は削除されているため、独自のログ監視・起動判定は見直します。level.datのversion_historyはworld更新履歴であり、data pack formatとは別です。
